FOI IMPLEMENTADA A POSSIBILIDADE DE O CONSUMIDOR DA API DE FATURAMENTO INFORMAR, NA PRÓPRIA REQUISIÇÃO, QUAL TABELA DE
PREÇO DEVE SER UTILIZADA NO CÁLCULO DO PEDIDO.

A NECESSIDADE SURGIU PORQUE O CITEL SALES PASSOU A DECIDIR A TABELA DE PREÇO POR CONTA PRÓPRIA, ATRAVÉS DE CONFIGURAÇÕES
NOVAS DO LADO DELE (CFG_OPTPSL E CFG_TABSAL). ATÉ AGORA A API SEMPRE DERIVAVA A TABELA PELAS REGRAS INTERNAS DO AUTCOM,
O QUE FAZIA O PREÇO EXIBIDO NO SALES DIVERGIR DO PREÇO CALCULADO PELA API.

A API NÃO PASSOU A CONHECER ESSAS CONFIGURAÇÕES, E ISSO É DELIBERADO. DECIDIR QUAL TABELA USAR É RESPONSABILIDADE DO
CONSUMIDOR; CALCULAR O PREÇO DADA A TABELA É RESPONSABILIDADE DA API. SE A API TIVESSE DE EMBUTIR A REGRA DE ESCOLHA DE
CADA CONSUMIDOR, CADA NOVO CLIENTE EXIGIRIA ALTERAÇÃO NO SERVIÇO COMPARTILHADO.

O CAMPO NÃO É OBRIGATÓRIO. QUANDO INFORMADO, ACEITA VALORES DE 1 A 7 E É RESPEITADO NO CÁLCULO. QUANDO OMITIDO OU VAZIO,

NESTA ORDEM AS CONFIGURAÇÕES CFG_UTAPTB, CFG_SUGTBP COM CFG_TBPSUG, A TABELA CADASTRADA NO CLIENTE (CADCLI.CLI_TABPRE),

ACESSO AO BANCO, ESPELHANDO A VALIDAÇÃO QUE JÁ EXISTIA PARA A TABELA DE PREÇO INFORMADA NO ITEM.

DURANTE A VALIDAÇÃO CONTRA A API FOI IDENTIFICADO UM DEFEITO NO CACHE DE PREÇO SUGERIDO. A CHAVE DO CACHE ERA MONTADA A

CHAVE, E A SEGUNDA RECEBIA O PREÇO DA PRIMEIRA POR ATÉ TRINTA MINUTOS, SEM ERRO ALGUM. A CORREÇÃO FOI INCLUIR A TABELA
DE PREÇO NA COMPOSIÇÃO DA CHAVE.

A MESMA AUDITORIA ENCONTROU OUTROS DOIS ATRIBUTOS AUSENTES DA CHAVE, ANTERIORES A ESTE REQUISITO E QUE AFETAM SOMENTE
