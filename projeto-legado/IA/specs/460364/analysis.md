-DESCRIÇÃO DO ALTERA:

[ 1 ] MOVER A CASCATA DE DERIVAÇÃO DO STATUS PARA O SQL

      O STATUS NÃO É COLUNA DA SSATSK: É DERIVADO DE _DTAINI, _DTAFIN, _RESULT, _SUCESS E _TYPERR
      NUMA CASCATA ORDENADA, HOJE ESCRITA EM DELPHI NO
      TCOTACAOGIROANDAMENTOSERVICE.FDERIVARSTATUS, SUPRIMENTO.SERVICES.COTACAO.CONSULTA.PAS LINHA
      90.

      SUBSTITUIR POR FSQLSTATUSDERIVADO, QUE DEVOLVE A MESMA CASCATA COMO UM CASE:

        CASE
          WHEN SST_DTAINI IS NULL                                        THEN 'PENDENTE'
          WHEN SST_DTAFIN IS NULL
           AND COALESCE(TRIM(SST_RESULT), '') = ''                       THEN 'PROCESSANDO'
          WHEN SST_SUCESS = 'S'                                          THEN 'CONCLUIDO'
          ELSE                                                                'ERRO'
        END

      O SELECT DAS DUAS CONSULTAS PASSA A TRAZER ESSA EXPRESSÃO COMO STATUS_DERIVADO, E O DELPHI
      LÊ A COLUNA EM VEZ DE RECALCULAR.

      MOTIVO: O GET DE LISTA DO BLOCO [ 3 ] FILTRA POR STATUS. COM A REGRA EM DELPHI SERIA PRECISO
      UM PREDICADO SQL EQUIVALENTE AO LADO, E DUAS ESCRITAS DA MESMA CASCATA DIVERGIRIAM NA
      PRIMEIRA ALTERAÇÃO — A LISTA PASSARIA A CLASSIFICAR DIFERENTE DA CONSULTA POR ID, SEM ERRO
      NENHUM APONTANDO PARA ISSO. ASSIM HÁ UMA DEFINIÇÃO SÓ, USADA PELO SELECT E PELO WHERE.

      * O COALESCE(TRIM(...), '') NÃO É ADORNO: É O EQUIVALENTE DO _RESULT.ASSTRING.TRIM.ISEMPTY
        QUE A REGRA TINHA EM DELPHI. SEM ELE, _RESULT NULO FARIA A COMPARAÇÃO DEVOLVER NULL, O
        WHEN NÃO CASARIA E TAREFA EM PROCESSAMENTO CAIRIA NO ELSE, COMO ERRO. *

      * A ORDEM DOS WHEN É A REGRA, E O CASE DO SQL AVALIA NA ORDEM ESCRITA. O TESTE DE _DTAINI
        NULA VEM PRIMEIRO PORQUE _SUCESS TEM DEFAULT 'N': AVALIADOS DE FORMA INDEPENDENTE, TODA
        TAREFA RECÉM-ENFILEIRADA SAIRIA COMO ERRO. O ÚLTIMO RAMO É O ELSE, E NÃO UM TESTE DE
        _SUCESS = 'N', PORQUE QUANDO O DISPARO FALHA O SERVICES.CORE.WORKER GRAVA _RESULT E
        _TYPERR MAS NÃO GRAVA _SUCESS. *


[ 2 ] EXPOR IDPROCESSAMENTO E IDRASCUNHO NO TCOTACAOGIROANDAMENTO

      ACRESCENTAR OS DOIS CAMPOS AO DTO DE RESPOSTA EM
      SUPRIMENTO.SERVICES.COTACAO.TYPES.PAS LINHA 633:

        idProcessamento : String          AUTOINCREM DA SSATSK
        idRascunho      : NullableString  SST_PARAMS ->> '$.sequencialRascunho'

      O SELECT DO FSQLSELECT TRAZ O RASCUNHO COMO COLUNA CALCULADA, PELA MESMA EXPRESSÃO QUE A
      COTACAO.CONCORRENCIA JÁ USA PARA NOMEAR O LOCK (LINHA 75). O ->> DEVOLVE NULL, E NÃO ERRO,
      QUANDO O CAMINHO NÃO EXISTE NO JSON.

      COMO O DTO É O MESMO DOS DOIS ENDPOINTS, O GET POR ID PASSA A DEVOLVER OS DOIS CAMPOS
      TAMBÉM — QUE É O QUE O CONSUMIDOR PEDIU PARA O IDRASCUNHO.

      * NULLABLESTRING E NÃO STRING NO IDRASCUNHO PORQUE O VALOR SAI DE JSON, E NÃO DE COLUNA:
        LINHA COM _PARAMS SEM O CAMPO NÃO TEM RASCUNHO A DECLARAR. STRING VAZIA SERIA LIDA COMO
        RASCUNHO DE SEQUENCIAL VAZIO. VALOR '' É TRATADO COMO AUSENTE JUNTO COM O NULO. *

      * FOI A ESCOLHA ORIGINAL DE NOMEAR O LOCK PELO RASCUNHO, EM VEZ DE CRIAR COLUNA, QUE
        DISPENSA MIGRAÇÃO AQUI. A SSATSK É COMPARTILHADA PELOS TRÊS SERVIÇOS E COLUNA NOVA NELA
        CUSTARIA MAIS DO QUE ESTE REQUISITO VALE. *
